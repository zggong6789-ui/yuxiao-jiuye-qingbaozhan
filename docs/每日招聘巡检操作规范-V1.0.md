# 豫校就业情报站 每日招聘巡检操作规范 V1.0

## 1. 用途与最高原则

本规范用于日常执行“今日招聘巡检”。目标是在不扩大来源库的前提下，从现有官方来源中稳定发现可供人工审核的高校及相关单位招聘公告。

项目服务本科、硕士、博士三类求职者。重点兼顾教师、辅导员、行政教辅、实验实训、科研助理、技能人才、高层次人才，以及其他符合项目定位的正规招聘岗位。

任何由 AI 生成、提取或判断的信息，最终均以官方原文和人工终审为准。未经人工审核，不得写入 `data/招聘信息表.csv`，不得作为公众号正式发布内容。

## 2. 每日使用的数据与文件

巡检开始前读取以下文件：

- `data/高校来源表.csv`：选择当天待检查的官方来源。该表有 13 个字段，重点使用“是否重点监控”“建议查看频率”“最后检查日期”“当前状态”“备注”。
- `data/招聘信息表.csv`：与候选公告去重。该表有 27 个字段，重点比对学校名称、公告标题、官方原文链接、公告发布日期、招聘类型和招聘批次。
- `docs/运营SOP-V1.0.md`：作为项目范围、核验和入库的上位规则。

巡检本身不修改上述文件。只有人工确认候选公告后，才进入正式入库流程。

## 3. 当天来源选择规则

每天优先检查 5—8 个来源。选择顺序如下：

1. `备注`中标注 P0 的已核验来源；
2. `是否重点监控`为“是”、`当前状态`为“已核验”的人事处、人才招聘、招聘系统和政府事业单位招聘栏目；
3. 按“建议查看频率”安排：标注“每周2次”或“每周3次”的来源优先于“每周1次”；招聘季按来源备注提升频率；
4. 优先选择距“最后检查日期”较久、近期曾连续发布招聘、或岗位覆盖不足的来源；
5. 在当天名单中尽量同时覆盖本科、硕士、博士，以及教师、辅导员、行政教辅、实验实训、科研助理、技能人才和高层次人才。

若来源表没有独立“优先级”字段，以“备注”中的 P0/P1/P2 为准；未标注优先级时，按上述第 2—4 条判断。官方公众号或“待核验”来源只作线索补充，不替代已核验官方网页。

## 4. 单个来源的巡检步骤

对当天每个来源依次执行：

1. 打开来源表中的“来源链接”，确认页面可访问且仍为官方页面。
2. 查看招聘栏目最新列表，重点查看招聘公告、人才招聘、人事处通知、招聘系统、政府事业单位招聘栏目；不把考试通知、资格审查、成绩、体检或拟聘公示当作新的普通招聘公告。
3. 对每一条疑似招聘，打开官方原文，记录学校/单位、标题、发布日期、官方链接和发现日期。
4. 如页面明确属于劳务派遣或人才派遣，立即排除，不进入候选表、招聘信息表、单篇文章或周报。
5. 如公告属于合同制或人事代理，不自动排除；保留官方原文表述，继续按本规范核验。
6. 如页面无法访问、附件打不开或公告关键信息缺失，标为“页面异常”或“待核验”，不推断缺失内容。

## 5. 新公告与去重判断

候选公告须先与 `data/招聘信息表.csv` 比对。依次检查：

- 学校/单位名称是否相同；
- 公告标题是否相同或高度相似；
- 官方原文链接是否相同；
- 公告发布日期、招聘年份、批次、岗位类型是否相同。

以下情况不新建普通招聘记录：

- 已入库公告的拟聘公示、考试通知、资格审查、体检通知；
- 已入库公告的补充、延期、取消、岗位调整等后续信息。

后续信息应作为原招聘记录的更新线索。正式更新时必须保存后续公告标题、发布日期、官方链接和具体变更内容，不得只写不可追溯的备注。

## 6. 当前有效性判断

按官方原文判断，不自行改写：

| 状态 | 判断方式 |
|---|---|
| 当前有效 | 官方原文可访问；未超过明确截止时间，或官方明确“年度有效”等表述；未发现明确终止通知。 |
| 即将截止 | 有明确报名截止时间，且距离截止不超过7天。 |
| 已截止 | 已超过官方明确报名截止时间。 |
| 已终止 | 官方明确发布取消、暂停、岗位取消、招聘完成等通知。 |
| 待核验 | 原文、日期、附件或后续状态无法确认。 |

“年度有效”不得自行改写为“长期有效”或“招满为止”。只有公告原文明确出现“招满为止”时，才可记录该表述。即使公告整体有效，也应提示具体岗位余缺需以学校最新信息为准。

## 7. 岗位性质与收录边界

- 劳务派遣、人才派遣：直接排除。
- 合同制、人事代理：可作为候选，但必须按官方原文填写，不得包装成事业编。
- 事业编制、备案制、聘用方式、工资待遇：只记录官方明确表述。公告未明确时，统一填写“公告未明确”。
- 不得因“公开招聘”“事业单位招聘”“工资按事业单位有关规定执行”等表述，自动判断有事业编。

## 8. 候选公告的最低核验项

对未排除且未重复的公告，至少核验：

1. 官方来源和原文链接；
2. 完整公告标题、发布日期、学校/单位名称；
3. 招聘人数、岗位类别、学历学位、专业、年龄及其他关键条件；
4. 报名方式、报名入口、报名截止时间或有效期原文；
5. 招聘流程；
6. 编制、备案制、人事代理、合同制、劳务派遣/人才派遣和待遇的官方表述；
7. 是否存在补充、延期、岗位调整、暂停、取消、招聘完成、拟聘等后续官方信息；
8. 是否已有附件。

岗位表、招聘计划、专业目录、报名表等附件是关键核验材料。AI 可以提示附件名称和待核对项目，但必须提示人工打开附件，确认岗位人数、专业、学历、岗位等级及其他关键条件后，才可正式入库。

## 9. 巡检输出与人工审核

巡检结束后，只输出“待人工审核候选表”和“来源检查情况”。AI 不写入招聘信息表，不生成正式发布结论。

候选公告可按以下标准建议处理：

- 深度解读：岗位覆盖核心人群、人数或条件有代表性、信息完整、学校关注度高，或岗位性质和待遇具有明确解释价值；
- 周报收录：人数少、学院单独招聘、条件常规，或与近期已解读公告相似；
- 暂不收录：信息不完整、已过期、与项目定位不符、重复，或需等待后续核验。

无论建议等级如何，候选表均为 AI 辅助结果，等待人工逐项对照官方原文审核。

## 10. 人工确认后的正式入库

人工确认可入库后，按 `docs/运营SOP-V1.0.md` 执行：

1. 为新公告分配编号，建议格式为 `JOB-年份-学校简称-序号`；
2. 只填写官方已确认的信息；未明确项写“公告未明确”；
3. 录入 `data/招聘信息表.csv` 的现有 27 个字段；
4. 录入后检查：仍为27字段、编号和官方链接无重复、原有记录完整、CSV格式无异常；
5. 仅在用户明确指令后执行 `git add`、commit 或 push。巡检和入库流程均不自动 commit，不自动 push。

## 12. 一句触发指令

以后用户说“执行今日招聘巡检”时，默认按本规范执行：从来源表选取当天 5—8 个重点官方来源，完成官方核验、去重、有效性和劳务派遣排除，并只输出待人工审核候选表，不修改任何数据文件。
